# Paymos для Paymenter

[English](README.md) | [简体中文](README.zh-CN.md) | **Русский** | [Español](README.es.md) | [Deutsch](README.de.md) | [Türkçe](README.tr.md)

Официальное расширение платёжного шлюза Paymos для **Paymenter v1.x** (Laravel / Filament).

Принимайте **4 стейблкоина (`USDT`, `USDC`, `USD1`, `DAI`)** и обеспеченный золотом токен **`XAUT`** в 13 основных сетях. Как только перевод подтверждается в блокчейне, шлюз фиксирует оплату штатным вызовом `ExtensionHelper::addPayment()` — Paymenter отмечает счёт оплаченным и автоматически запускает выдачу услуг и ваши правила автоматизации.

## Требования

- Paymenter v1.x (Laravel / Filament)
- PHP 8.2+ с расширениями `curl`, `hash`, `json`, `openssl` и `pdo`
- URL панели по **HTTPS** (`APP_URL`) — подключение по незашифрованному HTTP отклоняется
- Аккаунт Paymos с выбранным целевым проектом в личном кабинете Paymos

Запускать Composer на сервере Paymenter не нужно: релизный архив уже включает `paymos/php-sdk` по пути `Paymos/vendor/paymos/php-sdk/`. Интерфейс админки и тексты оплаты поставляются на 6 языках: английском (`en`), русском (`ru`), немецком (`de`), испанском (`es`), турецком (`tr`) и упрощённом китайском (`zh-Hans`).

## Установка и подключение

1. Скачайте актуальный архив `paymos-paymenter.zip` со страницы [GitHub Releases](https://github.com/Paymos-labs/paymenter/releases/latest).
2. Распакуйте архив в каталог `extensions/Gateways/` вашего Paymenter так, чтобы получилась следующая структура:

   ```text
   extensions/Gateways/Paymos/
     Paymos.php
     routes.php
     composer.json
     README.md
     CHANGELOG.md
     LICENSE
     src/
     resources/views/
     lang/
     vendor/paymos/php-sdk/
   ```

3. Если включено кэширование маршрутов или шаблонов, очистите кэш Laravel:

   ```bash
   php artisan route:clear
   php artisan view:clear
   php artisan config:clear
   ```

4. В разделе **Paymenter Admin → Extensions → Gateways** включите **Paymos**.
5. Откройте нужный проект в кабинете Paymos, затем нажмите **Подключить Paymos** (Connect Paymos) в настройках шлюза Paymos в Paymenter и подтвердите привязку во вкладке Paymos.

Все мерчанты скачивают один и тот же архив без зашитых ключей, ID проекта или секретов. Одно подтверждение атомарно настраивает обе среды — **Песочницу** (Sandbox) и **Рабочий режим** (Live) — и регистрирует подписанный обработчик вебхуков для этой установки Paymenter:

```text
https://<your-paymenter-panel>/extensions/gateways/paymos/webhook
```

После подключения в настройках шлюза доступны только два поля: **Подключение** (статус подключения и кнопка переподключения) и **Режим** (`Sandbox` или `Live`). Ручных полей для API-ключа, API-секрета, ID проекта или секрета вебхука нет нигде.

## Хранение секретов

Выданные ключи для Песочницы и Рабочего режима вместе с временным состоянием привязки устройства шифруются в аутентифицированном конверте **AES-256-GCM** (`AesGcmEnvelope`) с ключом на основе Laravel `config('app.key')` и сохраняются в `paymos_settings`. Секреты никогда не выводятся в HTML, логи или тексты ошибок. Если изменился URL панели, отозван Payment-ключ или перевыпущен секрет вебхука — выполните переподключение.

## Оплата и жизненный цикл счёта

- **Отказоустойчивое создание счёта:** перед отправкой `POST /v1/invoices` шлюз сохраняет намерение со статусом `creating` и при потере ответа повторяет запрос с теми же `external_order_id`, суммой, валютой, проектом и средой, не создавая дублей.
- **Позиции счёта и остаток к оплате:** на оплату берётся в первую очередь `$invoice->remaining` (поэтому частично оплаченные счета или счета с применённым кредитом выставляются ровно на остаток), а до 50 проверенных строк из `$invoice->items` передаются в `products[]`; если позиции недоступны или некорректны, оплата переходит в режим передачи одной итоговой суммы.
- **Безопасная замена счёта (fail-closed):** когда меняется сумма к оплате, валюта, режим или проект — либо истекает срок предыдущего инвойса Paymos — шлюз сначала закрывает старый счёт через `InvoiceReplacement::close()`, прежде чем выпустить новый. Если старый счёт уже оплачен, ещё доступен для оплаты, недостижим или вернул 404, замена блокируется до ручной проверки, чтобы покупатель не смог заплатить дважды.
- **Подписанные вебхуки и плановая сверка:**
  - Входящие вебхуки на `/extensions/gateways/paymos/webhook` проверяются для Песочницы и Рабочего режима через `MultiEnvironmentWebhookVerifier` (HMAC-SHA256 за постоянное время, двойной `v1=` при ротации секрета, окно метки времени 300 секунд) и дедуплицируются через атомарные резервации с привязкой к владельцу (`200` для уже обработанного дубля, `409` для параллельной доставки в обработке, `401` при неверной или устаревшей подписи).
  - Финальные события проходят живую обратную проверку (`GET /v1/invoices/{id}`), сверку сумм `AmountGuard` (`manual_review` + HTTP `400` при расхождении) и защиту от отката, чтобы оплаченные или закрытые счета никогда не понижались в статусе и не зачислялись дважды.
  - Событие `invoice.paid_late` обрабатывается строго как идемпотентная заметка с флагом `paid_late_noted` без автоматического зачисления.
  - `Paymos::boot()` регистрирует задачу в планировщике Laravel `Schedule` каждые 10 минут (с ограничением не чаще раза в 600 секунд): она проверяет до 50 неоплаченных счетов Paymos за последние 24 часа и сверяет ожидающие возвраты.

## Возвраты

Расширение поддерживает возвраты `full` и `overpayment` (`paid_over`) с расчётом суммы на сервере через Paymos Refunds API (`/v1/refunds`). Средства отправляются строго обратно на проверенный адрес `first_sender`, с которого пришёл исходный депозит — произвольные частичные суммы и ручной ввод адреса получателя отклоняются ещё до обращения к API:

- **Панель возвратов Paymos в админке счёта:** выводится через render-хуки Filament для администраторов с правом `admin.invoices.update`. Показывает статус операции, поддерживает действия `full` и (для счетов `paid_over`) `overpayment` с постоянным UUIDv4 `request_token` и защитой CSRF, а также находит возвраты, созданные напрямую в кабинете Paymos (`RefundDiscovery`).
- **Асинхронно безопасный `Gateway::refund()`:** поскольку `ExtensionHelper::refund()` в Paymenter синхронно вызывает `ExtensionHelper::recordRefund()`, как только `Gateway::refund()` возвращает `true`, метод `Paymos::refund()` никогда не возвращает `true`, пока возврат Paymos находится в статусе `pending`, `processing` или `unknown`. Когда Paymos подтверждает `completed` (через подписанный вебхук `withdrawal.completed` или плановую сверку), `RefundAdapter::applyCompleted()` ровно один раз фиксирует штатный возврат через `ExtensionHelper::refundLocally()` для `full` или добавляет заметку (оставляя счёт оплаченным) для `overpayment`.

## Решение проблем

- **Подключение не запускается:** проверьте, что `APP_URL` начинается с `https://`, а у учётной записи администратора есть право `admin.gateways.update`.
- **Маршруты возвратов возвращают HTTP 403:** эндпоинты подключения требуют права `admin.gateways.update`, а эндпоинты возвратов — `admin.invoices.update`; обычным клиентским аккаунтам намеренно возвращается HTTP `403`.
- **Оплаченный счёт задержан для ручной проверки:** откройте логи Laravel и найдите записи `Manual review` — либо сумма счёта изменилась после создания платёжной сессии, либо не удалось подтвердить закрытие старого инвойса Paymos перед его заменой.
